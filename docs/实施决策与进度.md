更新日期：2026-09-27。本文记录仓库实际实现，覆盖 [v0.1 项目书](比特严选项目书-v0.1-评审稿.md) 中已经确认或调整的部分。启动见 [README](../README.md)，AI 细节见 [AI 实现与验收](AI实现与验收.md)。

## 已落实的架构决策

| 选择 | 最终实现 |
| --- | --- |
| 微服务 | Gateway、Catalog、Commerce、AI 四个独立 Java 应用；contracts 共享 DTO、RPC 契约和认证基础设施 |
| 注册与通信 | Nacos 服务发现；CatalogRpc 提供实时商品，CommerceReadRpc 提供本人订单/钱包；服务间使用 Dubbo |
| 交易一致性 | 账户、钱包、库存、订单集中到 Commerce；单 MySQL 事务、行锁、条件更新、幂等键与流水共同约束 |
| 本地部署 | Java / IDEA 与 Next.js 在 Windows；中间件使用 WSL Docker 独立 bit-select 项目和持久卷 |
| 短期记忆 | 达到配置容量 60% 时摘要较早历史，保留最近约 20% 容量并向完整轮次扩展 |
| 语义切块 | 不使用 RFF；Embedding 段落相似度、标题和长度选择切点，两侧分别扩展至多 200 个 Qwen token |
| 长期记忆 | MySQL 保存事实、版本、原始对话和任务；RocketMQ 异步提取；Milvus / Neo4j 维护可重试的检索投影 |
| LambdaMART | 实际 LightGBM lambdarank 训练制品，Java 读树推理；标签来源、留出集结果和限制显式保存 |
| AI 供应商 | 硅基流动：Qwen3-30B-A3B-Instruct-2507、Qwen3-Embedding-4B、Qwen3-Reranker-4B |
| 前端 | Next.js + TypeScript + Ant Design；商城、交易、后台、流式导购、引用及个人记忆管理 |

使用 Java 21、Spring Boot 3.5.11、Spring Cloud 2025.0.2、Dubbo 3.3.5；AI 编排使用 Spring AI Alibaba Graph Core 1.1.2.2，模型兼容接口通过 Java HTTP 客户端调用。前端锁文件固定 Next.js 16.3.6、React 19.2.4、Ant Design 6.6.5。

当前共用一个 `bit_select` MySQL schema，按应用划分表和职责，没有每服务独立数据库、跨库分布式事务或跨机集群。将强一致交易收拢到同一服务，是单机演示的明确取舍。

## 已解决的实现问题

- Windows 运行 JAR 复制到 `.local/runtime`，避免文件锁阻断后续 Maven 构建；停止前核对 PID、UTC 启动时间、可执行文件及本仓库路径。
- Dubbo 3.3.5 不接受 `127.*` Provider 地址，本地 RPC 使用 IPv6 回环 `::1`，HTTP 使用 `127.0.0.1`；操作系统需要启用 IPv6 回环。
- WSL 可能在只剩 systemd 服务时自动退出，脚本保留本项目隐藏保活进程，停止时核验归属，没有修改 WSL 全局内存配置。
- RustFS / Milvus 通过 SigV4、path-style S3 对接，对象桶分离；RocketMQ 和 RustFS 新卷权限由一次性服务初始化。
- 手册指纹保留原始换行内容，并加入 `qwen-token-boundaries-v2` 版本，避免 CRLF 与 Python 默认换行转换导致指纹误判。
- 会话及切块使用 Qwen 原生 BPE，替代字符数近似；模型容量、正文 token 数与消息封装/输出余量分别管理。
- 钱以整数分储存，给模型的证据明确换算成人民币元；推荐先按预算、上架和库存过滤。
- 异步记忆比较原始消息顺序，延迟的旧任务不能覆盖新事实；删除/停用递增 generation，使过期队列任务不能写回。

## LambdaMART 的实际结果

默认制品来自 200 个自动商品指向查询、2,364 条真实候选。特征使用真实 Qwen Embedding、Qwen Reranker 与本地 BM25；标签为目录身份规则弱标注。按查询/商品关系连通组隔离，训练/验证/测试分别 135/30/35 个查询；验证集提前停止实际选择 1 棵树。

| 留出指标 | LambdaMART | Reranker 基线 | 差值 |
| --- | ---: | ---: | ---: |
| NDCG@5 | 0.979061 | 0.962848 | +0.016213 |
| NDCG@10 | 0.981392 | 0.942053 | +0.039339 |

这些结果只验证该弱监督数据上的排序和训练链路。候选池按互斥品类限制，查询包含商品身份，`exactProductMatch` 使任务较容易；没有人工开放式导购标签，不能据此宣称真实用户质量提升。来源、数据指纹和划分见 [训练报告](../data/ranking/evaluation.json) 与 [训练说明](../data/ranking/README.md)。

## 单机演示边界

这是单实例、有限数据量的功能演示。事务与幂等解决已覆盖的交易一致性问题，没有据此声称生产高可用、峰值吞吐或零丢失。没有真实收款、银行余额、物流承运商、短信实名、商品认证、分布式追踪平台与生产备份恢复演练。

AI 提供事实读取和解释建议，不代替用户付款、退款或分配余额。模型仍可能出错；跨存储投影最终一致，模型供应商或单节点故障会影响 AI 可用性。生产化需另补集群部署、持久任务调度、恢复演练、容量压测和独立人工评测，这些未完成事项不计入本次验收。
