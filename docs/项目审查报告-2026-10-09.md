## 剩余风险与运行语义

1. Outbox 采用至少一次投递。Broker 确认后、数据库完成标记前中断，仍可能重复发送同一事件；事件 ID 保持不变，消费者必须按事件 ID 幂等。此次公平重试解决阻塞，生产化仍需明确退避、死信和记录保留策略。
2. SSE 保存接纳前取消会阻止保存；完整回复已被接纳后，保存结果决定最终状态。此时关闭网页不会撤销成功提交的对话，可通过历史记录重新读取。数据库提交成功但网络确认丢失的歧义仍需结合历史记录核对。
3. MySQL、Milvus、图数据库和对象存储之间为最终一致投影。知识库以 PROCESSING/READY 限制可见性并允许重试，没有跨所有存储的原子事务保证。
4. 售后重新提交会重用订单对应的申请行并更新 ID。此次关闭旧审批影响新申请的风险，但完整保留每次拒绝与重提历史仍需要单独的审计表。
5. 当前部署是单机演示环境。生产高可用、峰值容量、故障切换、备份恢复和真实模型质量需分别压测与演练；本次审查不作这些能力的认证。

## 补充回归：检索中停止后立即重新回答

用户补充复现步骤为：在“查找说明书与偏好”阶段点击停止，随后点击重新回答。原先浏览器只断开 SSE，后端仍可能等待心跳发现断连并清理会话锁；重试因此触发 `CONVERSATION_BUSY`。错误响应又未显式声明 JSON，在请求只接受 SSE 时丢失原始状态和提示，页面显示通用失败。记忆召回中的降级处理还可能吞掉取消或中断，延后退出。

新增按请求 ID 取消的接口并校验用户归属；最多等待两秒，清理尚未结束时返回 202，前端有限轮询确认。页面在确认期间显示正在停止，确认后才恢复重新回答。会话锁及并发名额由原 worker 在退出时释放，保持此前 COMMITTING 保存接纳语义。所有公共 API 错误明确返回 JSON，前端兼容 JSON 与 SSE，仅对同会话的生成前锁冲突作有限重试。记忆召回及时传播取消，中间件普通故障仍按原策略降级。

本次完整 Maven `verify` 为 119 项测试（AI 79、交易 26、网关 8、公共契约 4、目录 2），失败、错误和跳过均为 0。前端 32 项测试、类型检查及生产构建通过。Next→Gateway→AI→本地模拟模型集成新增检索阻塞、跨用户取消拒绝、取消确认后立即重试和持久化隔离检查；重试前不再额外等待断连或读取历史。浏览器在完整生产页面上执行相同停止及重试顺序，最终正常收到完整回答，控制台无错误或警告。

以上验证使用隔离端口和模拟模型，无付费模型调用。临时知识记录使用独立 namespace 并在验证退出时清理。当前取消请求表位于单个 AI 实例内；多实例部署需要额外的请求路由或共享取消机制。

## 补充：全站光轨与曲面视觉重构

根据用户后续要求，更新此前偏方正的视觉方向。首页与商品详情改为椭圆商品展台、浮动光轨和开放式商品陈列；导航、筛选与操作入口使用胶囊形状。购物袋、钱包、地址和售后采用开放商品行与长曲面布局，订单使用圆形流程节点和可展开配送信息。导购使用浮动历史侧栏、开放对话舞台及曲面输入区；商城管理、知识入库、服务拓扑、AI 追踪和任务队列沿用同一视觉语言。200 张原有 SVG 商品插图移除矩形底板，商品数据和说明书正文不变。

互动背景使用原生 WebGL 与 CSS 光场，装饰不接收点击。绘制上限为每秒 30 帧及 700,000 像素，不在每帧更新 React 状态。输入聚焦、隐藏标签、窄屏、粗指针设备及系统减少动态效果偏好会暂停持续绘制；导航提供可保存的动效开关，商品倾斜和页面过渡也尊重该开关。WebGL 不可用时保留静态 CSS 背景，卸载清理资源与监听。结算、登录和运维页面收敛浮动入口，减少对表单与数据阅读的遮挡。

浏览器发现并修复了 320px 登录装饰越界、管理更新时间撑开容器、分类焦点轮廓裁切、导购外层多余滚动和页脚边距问题。调整浅色柔和背景及小字颜色，补齐链接可访问名称与站点图标，并将五处链接嵌套按钮改为单一 Next Link，保留客户端导航及键盘焦点。

首页首批真实商品与分类在服务端并发加载，禁用缓存，各自限定 1.5 秒等待且独立降级。初始 HTML 已包含主图的 `src`、`loading="eager"` 与 `fetchPriority="high"`；客户端继续刷新库存及处理筛选、分页与重试，取消检查防止旧请求覆盖当前结果。新增三项回归覆盖并发请求不携带账户凭证、超时或不可用时部分降级、无效 JSON 与字段隔离。
