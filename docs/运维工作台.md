# 运维工作台

管理员登录后，从账户菜单或商城管理页进入 [运维工作台](http://localhost:3000/admin/ops)。普通账号不会显示入口，直接访问页面会提示无权限；后端仍独立核验 Redis 登录态和数据库中的管理员角色，伪造身份请求头不能访问监控接口。

## 三个页面

### 运行概览

展示网关、商城、商品和 AI 服务的连接关系与最近探测结果，以及用户数、知识库索引和订单状态流程。订单流程中的数字表示当前处于该状态的订单数，并非转化率或完整行为埋点。

HTTP 探测读取服务的健康接口；TCP 探测只说明中间件端口是否可达，不能证明完整业务健康。探测结果有短时缓存，页面显示采样时间，失败或未知状态不会显示成正常。

### AI 对话链路

按请求展示问题摘要、用户 ID、会话 ID、状态、首字耗时、总耗时和实际执行阶段。选择请求可查看重写、意图识别、检索、回答生成、保存等阶段的时间轴。只有实际开始的阶段会出现，取消时不会补造后续步骤。首字耗时以服务端收到首段非空模型输出为准，字符数是进入服务端输出队列的模型生成 Unicode 字符数，不是客户端确认接收的字节数。

状态包括运行中、已完成、失败和已取消；超时保留 `AI_TIMEOUT` 错误码。超出请求期限仍没有终止记录的请求标记为遗留记录，方便排查服务重启或监控写入问题，不会自动当作成功。输出字符数在请求结束后统计。

该功能上线前的历史对话没有阶段追踪记录；请求通过鉴权、并发限制和会话锁后开始采集，进入 SSE 前被拒绝的请求不建链路记录。运维接口不返回模型提示词、密钥、完整回答和原始异常堆栈；问题仅保留有限长度摘要。阶段持久化使用有界异步队列，监控写入异常不阻断导购回答，列表可能短暂滞后。

### 消息队列

分别查看交易 Outbox 和长期记忆任务，提供状态筛选、分页和投递／消费流程图。

- 交易 Outbox：待投递、重试中、已投递。已投递表示 Broker 确认接收，不表示下游消费者已经处理；当前发布器没有终止重试策略。
- 长期记忆：待处理、处理中、重试中、完成、失败。`PROCESSING` 表示当前正在处理；失败且未达到重试上限的任务仍列为重试中，第八次处理尚未结束时不会提前标记失败。

这里的计数来自数据库可靠事件与任务记录，不是 RocketMQ Broker 的消费积压、消费位点或 TPS。RocketMQ 名称服务端口可达性是单独的探测指标。运维页只读，不提供重放、删除或更改任务状态按钮。

## 刷新与本地运行

页面支持手动刷新和自动刷新；隐藏页面时暂停自动刷新，重复请求不会叠加。读取失败会保留上次数据并提示错误及其更新时间。

后端新增表由 Flyway 的 `V5` 迁移创建。更新后重启 IDEA 的 `commerce-service` 和 `ai-service`，前端开发服务器会加载页面变更；中间件继续使用原有 WSL Docker 容器。


该验收检查管理员权限、伪造身份拒绝、实际汇总、分页与筛选，不调用付费模型。CI 还通过本地模拟模型发送实际 SSE 请求，核对完成、失败、超时、取消与改写中取消的追踪状态及阶段。

## 只读接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/admin/ops/overview` | 应用探测、订单流程、队列和知识库汇总 |
| `GET /api/admin/ops/events` | 交易与记忆任务的安全元数据分页 |
| `GET /api/admin/ops/events/{kind}/{id}` | 单条任务的最新状态，与列表筛选无关 |
| `GET /api/ai/admin/ops/summary` | 已采集 AI 请求状态汇总 |
| `GET /api/ai/admin/ops/requests` | AI 请求分页与状态筛选 |
| `GET /api/ai/admin/ops/requests/{id}` | 单次请求的实际阶段时间轴 |

分页参数 `page` 从 1 开始，`pageSize` 最大 50；非法筛选或分页返回 400。队列 `kind` 为 `commerce` 或 `memory`；状态为 `all`、`pending`、`processing`、`retrying`、`completed`、`failed`。AI 请求状态为 `all`、`running`、`completed`、`failed`、`cancelled`，可用 `userId` 筛选。
